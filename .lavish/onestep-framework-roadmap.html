1onestep

从“能连接”走向“可信运行”

接下来的竞争力不来自更多 YAML 语法或更多插件，而来自数据不会被静默跳过、生产失败能够本地复现、故障能够被快速恢复。

产品定位：代码优先的数据任务运行时。Python 负责业务转换；YAML 只负责资源、策略与 handler.ref 的装配。

当前判断

已完成 连接器广度Elasticsearch、ClickHouse、MongoDB 已进入 main；现阶段无需用插件数量证明框架价值。
已完成 凭据脱敏最近提交已覆盖九类连接器，旧审查结论不再作为未完成项。
仍有风险 正确性边界模糊写入重试、游标 generation gap、持久化失败和直接 API 校验仍需先解决。

P0 已确认的四类缺口

Elasticsearch / 重复风险

模糊网关响应不应自动重放 auto-ID 写入

请求体发送后收到 502/503/504，后端是否已提交无法确定。没有稳定 ID 时，内部重试可能制造重复文档。

MongoDB / 跳数风险

later ACK 后的 earlier retry 必须作废整个 generation

后一个 token 已 ACK、前一个随后 retry 时，不能把后一个 token 写入持久游标。

MongoDB / 状态风险

状态保存失败不能先推进内存游标

只有 durable state 确认保存后，才能移除 contiguous prefix 并更新内存 committed token。

MongoDB / 配置风险

Python 直连 API 与 strict YAML 必须同样严格

batch_size=0、非法时间参数和排除 cursor 字段的 projection 应在构造阶段失败。
