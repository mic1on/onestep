有序路线图

每一阶段都有明确退出门槛。只有前一阶段把质量能力固化后，才扩大框架表面或连接器数量。

阶段状态主要交付退出门槛
P0已完成修复模糊重试、游标状态、持久化失败与 Python 直连校验缺口。受影响插件回归与可靠性套件通过。
P1已完成按 source、checkpoint、claim release、sink ACK、重放安全与公开错误声明能力。全部官方插件声明能力并通过适用契约。
P2下一阶段单条本地执行、Envelope 捕获/重放、check --connect、Handler 测试脚手架。无需 Worker 或 Control Plane 即可复现已捕获的生产 Handler 失败。
P3规划中稳定 delivery 关联值、独立 attempt、lag/cursor/retry 指标、恢复操作审计。操作员可在 Control Plane 定位失败投递及完整尝试链路。
P4规划中create-plugin 脚手架、目录校验、兼容矩阵、支持等级、CI 模板。社区插件无需复制官方插件即可通过契约套件。
P5需求驱动S3/MinIO 优先候选；NATS JetStream 及云/SaaS 连接器需真实用户证据。已确认工作负载无法由现有连接器干净覆盖。

阶段依赖

下一阶段需要先定的三个决策

P2 运行器边界

泛化现有 run_task_once()，还是引入独立 diagnostic runner；不能复用远程 manual-run 语义造成耦合。

P2 捕获安全

Envelope 格式必须版本化、JSON-safe，并默认脱敏；本地重放默认 dry-run，显式选择才发送到 sink。

P3 协调窗口

delivery/attempt 字段会穿过 runtime、reporter、后端存储与前端，必须以 additive payload 同步演进。

成功指标

< 10 分钟新任务到首次本地成功投递
≥ 90%生产 Handler 失败可本地复现
100%官方连接器声明 conformance profile
≥ 95%公开连接器错误归一化分类
< 5 分钟失败投递定位并重放
< 1 工作日社区插件到通过契约套件

明确不进入路线图

  • YAML 字段转换语言
  • 官方领域业务 Handler 库
  • Airflow/Temporal 式 DAG 编排
  • file-tail/syslog 日志 Agent 定位
  • 数据库 DDL 或迁移所有权
  • exactly-once 承诺
  • 连接器数量 KPI
  • 恢复能力未落地前新增 Control Plane 表面
